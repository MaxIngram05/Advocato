# Decisions log

Every choice made beyond the build prompt is listed here with the prompt section it relates to.

| # | Section | Decision | Reason |
|---|---|---|---|
| D1 | §9.2 | Per-call `UrlFetchApp` timeout is **not documented** on Google's quota page (checked 2026-10-16, https://developers.google.com/apps-script/guides/services/quotas). Documented limits: 6 min per script execution, 50 MB response, 50 MB POST, 20 000 (consumer) / 100 000 (Workspace) fetches per day. We keep one LLM task per RPC so the 6-min bound holds against Augure's ~240 s non-streaming timeout. | No relay backend is added unless live calls show timeouts (then we ask). |
| D2 | §9.2 / §0 | Toolchain pins: React 18.3.1 (spec), TypeScript 5.9.2, Vite 6.3.5, Vitest 3.2.4, zod 3.25.76 (works with `zod-to-json-schema`), ESLint 9 + typescript-eslint 8 strict, Playwright 1.55. | Stable versions known to work together; spec asks for React 18 and zod-to-json-schema. |
| D3 | §9.2 | Server bundle: esbuild IIFE with global `__avocado`; `scripts/build-server.ts` appends a top-level `function <name>()` stub per export. | Apps Script only treats declared functions as triggers/menu targets/`google.script.run` endpoints. |
| D4 | §9.2 | `appsscript.json` sets `urlFetchWhitelist` for Augure, CAIJ and LégisQuébec. | Required for a published Editor add-on; harmless in dev. |
| D5 | §17 | Architecture boundaries are enforced with `eslint-plugin-boundaries` (`eslint.config.js`). | Spec allows this tool or dependency-cruiser. |
| D6 | repo | The app lives in `avocado/` inside the existing `Advocato` repo; root `.gitignore` conflict markers (left by a merge) were resolved by keeping both entries. | Existing repo already holds unrelated files. |
| D7 | §6 US-02 vs §7 | `documents` is a required intake field, but §7 places UPLOAD after INTAKE_COMPLETE. `checkIntake(draft, { stage: 'intake' })` ignores `documents` to leave INTAKE; the full check (documents included) gates analysis (G9). | Keeps both the state machine and US-02. |
| D8 | §6 US-02 / G10 | Documents arrive after intake, so a stance suggestion at intake can only come from the intake chat text (`suggestStance`). After upload, a document-based suggestion may be shown; changing the stance then follows the §7 stance-change invariant. A suggestion is never applied without a click. | Documents are not available yet during intake. |
| D9 | §6 US-03 | Exhibit prefix follows the confirmed stance: claimant `P-n`, defendant `D-n`, other `I-n`. Numbering continues after the highest existing number. Numbering refuses to run without a confirmed stance. | Québec practice numbers exhibits per party; the prefix is derived, never assumed. |
| D10 | §6 US-03 | pdfjs-dist runs its worker module on the main thread (`globalThis.pdfjsWorker`) instead of a separate worker file. Upload size cap: 25 MB (Augure's file limit, so scanned PDFs can be sent for OCR). | The sidebar is a single inlined HTML file on a sandboxed origin; a separate worker URL is not available. |
| D11 | §9.5 | Added an `ExhibitStore` port (`put`/`get` segments) for exhibit text kept outside the case JSON. Exhibit text is stored as `{ locator, text }[]` segments (`p. n` for PDF pages, `para. n` for DOCX/TXT paragraphs). | §12 requires separate Drive files; ISP favors a small dedicated port over growing `CaseRepository`. |
| D12 | §10.2 | `response_format` is sent as `{ type: 'json_schema', json_schema: { name: <task>, schema } }` (OpenAI shape). Augure's docs (checked 2026-10-16) list `json_schema` but give no sub-fields; the live contract test (`LIVE=1`) confirmed `ossington-4-1` accepts it. The JSON Schema comes from `zod-to-json-schema` with `$refStrategy: 'none'`. | Spec gives the shape; docs are silent; verified live. |
| D13 | §10.2 | Reasoning effort for tasks the spec does not list: `suggestStance` low, `transcribePdf` low, `assessDamages` medium, `draftDocument` medium. | Same tiering as the listed tasks of similar difficulty. |
| D14 | §14.3 | Downgrade on the second grounding failure: unknown citation/fact ids are removed from id lists; an array element that itself points at a missing exhibit/fact/source is dropped; an object that lost fact/exhibit evidence and has a fact `status` becomes `hypothesis`. Removed ids are listed in the warning alert. A second *schema* failure throws `LlmOutputInvalidError` (unparseable output cannot be downgraded). | Keeps output schema-valid while never keeping an ungrounded reference. |
| D15 | §10.2 | `LlmRequest` gained `compactUser` (smaller context for `length`/504 retries) and `preferLongContext` (ContextPacker over budget). Truncation order: compact context on the same model, then `rosedale-1`, then `LlmTruncatedError`. | The client cannot shrink context itself; the caller supplies the compact version. |
| D16 | §14.1 | Added LLM tasks `suggestStance` (US-02 suggestion) and `transcribePdf` (scanned PDFs, §10.2) to the 13 listed tasks. | Both behaviours are required by the spec but had no task name. |
| D17 | §9.2 / §12 | Drive storage goes through the Drive v3 REST API (`UrlFetchApp` + `ScriptApp.getOAuthToken()`), not `DriveApp`. | Google's reference lists only `drive`/`drive.readonly` for `DriveApp.createFile`/`getFileById` (checked 2026-10-16); the spec's minimum scopes include only `drive.file`, which the REST API honors for files the app creates. |
| D18 | §9.2 | One RPC entry point `avocadoRpc(method, argsJson)` returning a JSON string `{ok, value | error}`; the server function is `async`. **To verify on the first `clasp push`:** that `google.script.run` delivers the resolved value of the returned Promise. Apps Script runs promise callbacks before an execution ends, but Google does not document Promise return values for `google.script.run`. If it does not, switch `avocadoRpc` to a synchronous driver. | Avoids GAS serialization quirks; single typed client (`RpcGateway`) shared by the GAS and in-process gateways. |
| D19 | §9.2 | Every RPC receives the client's current `CaseFile` and persists the result before returning (the sidebar is the source of truth during a session; the server is authoritative for what is stored). | Avoids stale reads between the debounced UI save and server calls. |
| D20 | §6 US-04 | Fact excerpts are checked against the stored exhibit text (whitespace/quote-insensitive). A reference whose excerpt is not found is removed (warning alert), its locator corrected when found on another page; a fact left without sources becomes `hypothesis`. Facts are extracted one exhibit per RPC. | G1/G3: no unverifiable quotation; one LLM step per RPC (6-min limit). |
| D21 | §14.1 / G10 | `detectMissingInfo`, `suggestStance` and `transcribePdf` use a neutral charter (no perspective, no stance needed); every other task requires the confirmed stance. | A suggestion must be possible before the stance exists, without presupposing it. |
